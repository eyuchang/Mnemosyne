# R85 REALM Tier-6 Live LLM Score Bridge

## Purpose

R85 adds a deterministic REALM-facing score bridge for the runtime-evaluated live-LLM Tier-6 records.

It reads the R84 runtime evaluator report and produces stable proxy metrics that prepare the path for official REALM scoring integration.

## Position in the Sequence

- R83.5a: manual live-LLM response packs
- R83.5b: deterministic comparison/import report
- R83.5c: deterministic kernel-admission trace attachment report
- R84: deterministic runtime replay/evaluator report
- R85: deterministic REALM score-bridge report

## Input

Default input:

- `results/realm_tier6_live_llm_manual/runtime_evaluator_report/runtime_evaluator_report.json`

This file is generated by:

    python benchmarks/realm/tier6_live_llm_runtime_evaluator.py evaluate

## Command

    python benchmarks/realm/tier6_live_llm_realm_score_bridge.py score

Default output:

- `results/realm_tier6_live_llm_manual/realm_score_bridge_report/realm_score_bridge_report.json`
- `results/realm_tier6_live_llm_manual/realm_score_bridge_report/realm_score_bridge_report.md`

## Metrics

R85 separates:

- clean admissions
- flagged admissions
- protective rejections
- unsafe admissions
- unsupported-specificity pressure
- admission-adjusted utility proxy
- grounded admission rate
- post-admission availability rate
- protective screening rate

These are deterministic proxy metrics, not official REALM scores.

## Claim Boundary

R85 phase 1 is a deterministic score-bridge report.

It does not claim:

- official REALM scoring
- API-automated LLM behavior
- production CTL-domain StateView realization
- confirmatory Chapter 6 evidence
- proof of AGI, wisdom, or autonomous scientific reasoning

Mnemosyne still owns admission. REALM still owns scoring.

## Next Step

R86 should connect this bridge to the actual REALM Tier-6 scorer so live-LLM packs can be evaluated with official REALM metrics after Mnemosyne admission.
